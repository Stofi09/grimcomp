# Sourcebook coverage and imports

The requested scope is the **WFRP Fourth Edition Core Rulebook** and **Winds of Magic**. The bundled catalogue is **incomplete**. Entries with `rulesStatus: "bibliographic"` are indexes; `"approximate"` marks provisional summaries. An absent status does not establish accuracy. Core career schemes also receive approximate runtime fallbacks on web.

## Reproduce the inventory

From the repository root:

```sh
pnpm run audit:content
node scripts/content-coverage.mjs --json > /tmp/grimcomp-content-coverage.json
pnpm run test:content-audit
pnpm --dir web exec vitest run src/content/contentCoverage.test.ts src/content/nativeBundledContent.test.ts
```

The report reads the web manifest, counts each effective entity after ID overrides and deletions, distinguishes authored rules statuses, and lists placeholder fields and source citations per entry in JSON output. It checks duplicate IDs. The registry comparison test verifies that these inventory counts match what the web app loads. The report does not count a citation, a summary, or a passing schema check as proof of sourcebook completeness.

The existing Winds pack includes 200 spells: 133 index entries and 67 approximate summaries. It also includes 12 indexed careers that are unavailable at creation. The remaining Core entries and the rules tables still need source comparison. Counts for the merged catalogue are generated by the command above; overlapping IDs are counted once.

Casting-number audit found 195 entries previously set to `99`. For 65 approximate overlaps, the pack now retains the existing older companion value with an explicit note. For 130 bibliographic entries, `cn: null` represents unknown data and prevents cast resolution or pool consumption. The five previously sourced numeric revisions remain unchanged. Restoring an older approximate value does not verify the Winds rule; these entries still require source comparison. The coverage report counts unknown CNs separately.

## Online sources checked on 7 September 2026

- [Cubicle 7 Core errata, version 1.1](https://cubicle7games.com/media/pdf/WFRP_Errata_28_Feb.pdf): freely published corrections. This supports the targeted talent and weapon corrections covered by `coreErrata.test.ts`; it is not a replacement for the complete Core Rulebook.
- [Cubicle 7 Winds of Magic PDF](https://cubicle7games.com/en_US/winds-of-magic-pdf): official product and sample access. The full PDF requires access through the publisher or the purchaser's platform.
- [Official Winds sample](https://cubicle7games.com/en_EU/downloadable/download/sample/sample_id/27/): seven preview pages, with credits dated 27 May 2022. Its contents page confirms the existing career and skill page references, but it contains no spell casting numbers or spell mechanics.
- [Cubicle 7 PDF update notice, 22 December 2023](https://cubicle7games.com/en_US/blog/Warhammer%20Fantasy%20Roleplay%20PDF%20updates): confirms revisions to Winds spell text, careers, casting, rituals and constructs. Import against the current owned edition and record its revision.
- [Official Winds of Magic Foundry module](https://cubicle7games.com/en_US/warhammer-fantasy-roleplay-the-winds-of-magic-foundry-module): a complete licensed module with journals, items, actors and tables. Foundry item counts are not interchangeable with spell counts.
- [Foundry release 9.6.4, Winds module 7.1.1](https://github.com/moo-man/WFRP4e-FoundryVTT/releases/tag/9.6.4) incorporates [spell issue #2533](https://github.com/moo-man/WFRP4e-FoundryVTT/issues/2533). This supports correcting the Winds entry for Let the Four Winds Blow! to a radius of four times Willpower Bonus yards. Its other mechanics remain approximate; the issue does not provide the complete spell.
- [WFRP4e Foundry system repository](https://github.com/moo-man/WFRP4e-FoundryVTT): explains that full rules content was removed from the free system and moved to official modules. Older forks are not a substitute for an authorized source.

Public sources did not supply an openly licensed, complete rules dataset for both books. No full sourcebooks or licensed module exports were supplied for this import. No book-completeness claim can therefore be made from this work.

## Finish the source comparison

Use locally supplied PDFs or licensed exports to check the following against a source inventory:

1. Every Core skill and talent, including groups, maxima, tests and specializations.
2. Every Core blessing, miracle and deity, with source-specific range, target, duration and effects.
3. Every spell and lore in both books, replacing indexed and approximate fields without losing existing character IDs.
4. Every career rank, status, scheme, skill/talent choice and requirement. Only enable reference-only careers for creation after their required creation data is present.
5. Rules chapters and tables, including conditions, injuries, psychology, equipment and magic. Winds needs more than spells: check rituals, familiars, constructs, elemental summoning, magical sites, arcane marks, grimoires, potions and associated tables.
6. Species, equipment, traits and other source material within the agreed two-book scope. Keep later supplements and other Warhammer editions distinguishable.

The web **Content** editor accepts spells, prayers, talents, skills, careers, species, equipment, deities, generic rules references and roll tables. Import existing-format JSON through **Settings → Content packs**, or edit the bundled packs under `web/public/content`. References can use any descriptive category; Reference search and category cards expose it automatically. Roll tables use `tables`, with explicit numeric bounds, outcome text, and optional dice.

Use the existing entity ID to replace an entry; adding a new ID would leave both versions visible. Preserve source book/page and any revision note supported by the entity schema. Store a citation in a reference's `meta` field where dedicated provenance fields are unavailable. Keep unresolved entries marked as such. This project does not currently convert Foundry exports or PDFs automatically.

## Native catalogue

The native app projects the web catalogue through `src/content/bundled.ts`, sharing the same JSON rather than maintaining a second smaller inventory. It keeps native rule-engine configuration and v1 user-pack import semantics. Additional v2 rules descriptions are browsable references, not newly automated native mechanics. Legacy native spell IDs remain resolvable for saved characters without duplicating the searchable catalogue.

If a new bundled pack is added to the web manifest, add its static native import as well; the native parity test catches omissions. Full v2 user-pack compatibility on native remains separate work.
